# SORP · разбор процессов

Плагин для Claude Code. Ведёт разбор бизнес-процессов: спрашивает то, чего не
хватает в реестре, и кладёт ответы обратно в реестр. Ставится и начинает
работать без единой команды — Claude сам спросит, как вас зовут.

---

## Что плагин отправляет. Прочитайте это до установки

Всё уходит на стенд SORP — в общий журнал разбора, который видят все его
участники.

**Всегда, без отдельного согласия:**

- **ваше имя** — когда вы им назоветесь. Без имени плагин не работает: разбор
  ведётся сообща, и решение без автора через месяц никому ничего не скажет;
- **ваши решения в разборе** — «подходит» или «не подходит, и вот чем», с
  вашим именем и временем. Ради этого разбор и ведётся.

**Только если вы согласились** (по умолчанию выключено):

- **текст ваших вопросов Claude**, время, имя папки проекта, из которой вы
  спрашивали, и номер сессии — чтобы вопросы одного разговора читались вместе.

**Никогда:** ответы Claude, содержимое ваших файлов, код, вывод команд, полный
путь к проекту на вашем диске.

**Зачем журнал:** чтобы через месяц можно было понять, кем и что спрашивалось и
решалось при разборе процесса, а не восстанавливать по памяти.

Согласие на запись вопросов отзывается одной командой. Записанное раньше при
этом остаётся на стенде: журнал, из которого можно вычистить свои следы, ничего
не стоит.

Если это вам не подходит — не включайте согласие или не ставьте плагин. Это
нормальный выбор.

## Установка

В Claude Code, двумя командами:

```
/plugin marketplace add https://github.com/sorp-pro/AI-Workflow-Builder.git
/plugin install sorp-svod@sorp
```

Потом начните новую сессию — знакомство начинается с её старта.

Адрес полный, с `https://`, нарочно: короткий `sorp-pro/AI-Workflow-Builder`
Claude Code клонирует по SSH, и без SSH-ключа к GitHub установка падает.

Из обычного терминала — то же самое:

```bash
claude plugin marketplace add https://github.com/sorp-pro/AI-Workflow-Builder.git
claude plugin install sorp-svod@sorp
```

**Не клонируйте репозиторий и не давайте Claude ссылку со словами «поставь».**
Так получится копия кода в папке, а не плагин: хуки не запустятся, и
знакомства не будет.

Нужен Node.js 20 или новее — он уже есть, если у вас работает Claude Code.

## Первый запуск

Никаких команд. Claude сам спросит, как вас зовут:

```
Claude:  Как вас зовут?
Вы:      Пётр Иванов
Claude:  Вы вошли как Пётр Иванов. Ваш ключ: sorp_… — сохраните его.
         Вопросы пока не записываются. Начинаем разбор?
```

Ключ выписывается на вашем ответе и запоминается сам. Показывается он один
раз — сохраните: в базе лежит только отпечаток, восстановить оттуда нельзя.
Ключ ваш и ни с кем не совпадает: занятое имя регистрацию не пройдёт, а не
подменит чужой.

Дальше сразу идут вопросы разбора — те места реестра, где чего-то не хватает.
Их не нужно ни у кого получать файлом: их знает стенд.

Имя занято — регистрация не пройдёт: двух одинаковых имён в журнале быть не
должно, а по чужому имени потом не разобрать, кто что решал. Назовитесь иначе
или войдите своим ключом.

Стенд может быть открыт для всех, спрашивать код приглашения или не пускать
никого — это решает тот, кто его ведёт. Плагин про это не знает: он посылает
имя, а что ответит стенд, вы увидите в ответе. Если код спросят, скажите его
так: `/vhod "Пётр Иванов" КОД` — или положите один раз в окружение,
`SORP_INVITE=…`, и вводить его не придётся.

## До входа плагин не пропускает вопросы

Разбор ведётся сообща, и вопрос без автора через месяц никому ничего не
скажет — поэтому до знакомства плагин останавливает обычные запросы и говорит,
что делать. Сам вход и разговор о нём он пропускает всегда: дверь, запертая
изнутри, — не дверь.

Это про имя, а не про запись обращений: войти обязательно, отдавать свои
вопросы — нет. Работать вовсе без входа:

```bash
export SORP_SKIP_LOGIN=1
```

## Ещё команды

Обычно они не нужны — плагин делает всё сам. Но если ключ у вас уже есть:

```
/vhod --ключ sorp_…
```

Включить запись обращений, если не против:

```
/vhod --согласие
```

## Работа

Разбор начинается сам, сразу после знакомства. Вернуться к нему потом:

```
/razbor
```

Вопросы приходят со стенда — это места, где реестр не заполнен: у шага не
назван стол, у гейта не названо условие, у поля не названо, что в него
записывается. Claude берёт их небольшими пачками, спрашивает кнопками и
кладёт ваши решения обратно на стенд сразу, а не в конце разговора.

При каждом вопросе он называет **основание** — на чём стоит предложенное:
`из реестра`, `из правила`, `по аналогии` или `догадка`. Догадка так и
названа догадкой: помеченная догадка видна и оспорима, непомеченная тихо
становится правдой реестра.

Не знаете ответа — так и скажите. Незакрытое место видно и когда-нибудь
закроется; закрытое наугад не видно никогда.

## Где что лежит

| Что | Где |
|---|---|
| Ключ и согласие | `~/.sorp-svod/nastroyki.json`, права 600 |
| Адрес стенда | зашит в плагин, меняется `SORP_API_URL` |
| Код приглашения | `SORP_INVITE`, если стенд его спрашивает |
| Требование входа | снимается `SORP_SKIP_LOGIN=1` |
| Ваши обращения | стенд SORP, если согласие включено |

## Команды

| Команда | Что делает |
|---|---|
| `/vhod` | кто вошёл и включена ли запись |
| `/vhod "Имя" КОД` | войти, когда стенд спрашивает код |
| `/vhod --ключ …` | войти готовым ключом |
| `/vhod --согласие` | разрешить запись обращений |
| `/vhod --отозвать` | запретить запись |
| `/vhod --выйти` | забыть ключ на этой машине |
| `/razbor` | вернуться к вопросам разбора |

## Как устроено

Два хука. Первый, при старте сессии, говорит Claude, с кем он работает, —
аналитику и настройщику нужны разные вопросы, и агент, не знающий роли,
обращается ко всем одинаково, то есть ни к кому. С незнакомым он делает другое:
просит Claude спросить имя и больше ничего пока не делать.

Второй стоит на входе каждой реплики и делает три вещи. Ловит имя: ответ на
вопрос «как вас зовут» он превращает в участника и ключ прямо на месте — вот
почему команд вводить не приходится. Называть себя человек умеет, а помнить
`/vhod` — нет. Не пропускает неназвавшегося — это единственное, что он
запрещает, и запрет снимается одной строкой, названной прямо в тексте отказа.
И записывает вопрос, если человек на это согласился, — вот здесь он падает
молча: плагин, ломающий работу из-за недоступной сети, снимут в первый же
день, и тогда не будет ни журнала, ни пользы от него.

Имя он проверяет, прежде чем заводить участника: ответить на вопрос об имени
человек может и вопросом по делу, а записать «а можно посмотреть шаг 3?» как
имя — значит закрепить это за ним навсегда. Переименовать участника нельзя,
только завести второго и разорвать след пополам.
