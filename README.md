# SORP · разбор процессов

Плагин для Claude Code. Ведёт разбор бизнес-процессов: показывает, чего не
хватает в описании, задаёт недостающие вопросы и собирает ответы файлом,
который возвращается в общий реестр.

---

## Плагин записывает ваши вопросы. Прочитайте это до установки

Если вы дадите согласие, **текст ваших вопросов** уходит на стенд SORP и
ложится в общий журнал разбора под вашим именем.

**Что записывается:** только то, что вы пишете Claude, время и имя проекта, из
которого спросили.

**Что не записывается:** ответы Claude, содержимое ваших файлов, код, вывод
команд.

**Зачем:** чтобы через месяц можно было понять, кем и что спрашивалось при
разборе процесса, а не восстанавливать по памяти.

**Согласие спрашивается отдельно от установки** и по умолчанию выключено. Без
него плагин работает так же — просто ничего не отправляет. Отозвать можно в
любой момент одной командой. Записанное раньше при этом остаётся на стенде:
журнал, из которого можно вычистить свои следы, ничего не стоит.

Если это вам не подходит — не включайте согласие или не ставьте плагин. Это
нормальный выбор, и он ничего не ломает.

## Установка

```
/plugin marketplace add sorp-pro/AI-Workflow-Builder
/plugin install sorp-svod
```

Или напрямую:

```bash
claude --plugin-dir /путь/к/AI-Workflow-Builder
```

Нужен Node.js 20 или новее — он уже есть, если у вас работает Claude Code.

## Первый запуск

```
/vhod
```

Больше ничего вводить не нужно. Имя плагин возьмёт из `git config user.name` и
покажет, откуда взял; ключ выпишет стенд. Имя не то — назовите своё:
`/vhod "Ваше имя"`.

Ключ показывается один раз — сохраните: в базе лежит только отпечаток,
восстановить его оттуда нельзя. Ключ ваш и ни с кем не совпадает: занятое имя
регистрацию не пройдёт, а не подменит чужой.

**Код приглашения.** Журнал общий, а репозиторий открытый — без кода писать в
него мог бы кто угодно. Код выдаёт тот, кто ведёт стенд:

```
/vhod "Ваше имя" КОД-ПРИГЛАШЕНИЯ
```

Чтобы участники не вводили его руками, положите код один раз в окружение —
тогда `/vhod` проходит от начала до конца сам:

```bash
export SORP_INVITE=…
```

## До входа плагин не пропускает вопросы

Разбор ведётся сообща, и вопрос без автора через месяц никому ничего не
скажет — поэтому до `/vhod` плагин останавливает обычные запросы и говорит,
что делать. Сам вход и разговор о нём он пропускает всегда: дверь, запертая
изнутри, — не дверь.

Это про имя, а не про запись обращений: войти обязательно, отдавать свои
вопросы — нет. Работать вовсе без входа:

```bash
export SORP_SKIP_LOGIN=1
```

## Ещё команды

Есть готовый ключ:

```
/vhod --ключ sorp_…
```

Включить запись обращений, если не против:

```
/vhod --согласие
```

## Работа

```
/razbor
```

Нужен файл разбора — `razbor-<дата>.md` от того, кто ведёт стенд. Внутри
вопросы по вашим процессам, варианты настройки Zoho CRM и план. Claude ведёт
по ним, спрашивает кнопками и собирает ответы файлом.

Ответный файл вернётся в реестр, и в журнале останется, кто отвечал и когда.

## Где что лежит

| Что | Где |
|---|---|
| Ключ и согласие | `~/.sorp-svod/nastroyki.json`, права 600 |
| Адрес стенда | зашит в плагин, меняется `SORP_API_URL` |
| Код приглашения | `SORP_INVITE`, если положен заранее |
| Требование входа | снимается `SORP_SKIP_LOGIN=1` |
| Ваши обращения | стенд SORP, если согласие включено |

## Команды

| Команда | Что делает |
|---|---|
| `/vhod` | войти: имя из git, ключ со стенда. Уже вошли — покажет, кто |
| `/vhod "Имя"` | войти под своим именем |
| `/vhod "Имя" КОД` | то же, с кодом приглашения в руках |
| `/vhod --ключ …` | войти готовым ключом |
| `/vhod --согласие` | разрешить запись обращений |
| `/vhod --отозвать` | запретить запись |
| `/vhod --выйти` | забыть ключ на этой машине |
| `/razbor` | вести разбор по файлу |

## Как устроено

Два хука. Первый, при старте сессии, говорит Claude, с кем он работает, —
аналитику и настройщику нужны разные вопросы, и агент, не знающий роли,
обращается ко всем одинаково, то есть ни к кому.

Второй стоит на входе каждого вопроса и делает две разные вещи. Не пропускает
неназвавшегося — это единственное, что он запрещает, и запрет снимается одной
командой, названной прямо в тексте отказа. И записывает вопрос, если человек
на это согласился, — вот здесь он падает молча: плагин, ломающий работу из-за
недоступной сети, снимут в первый же день, и тогда не будет ни журнала, ни
пользы от него.
