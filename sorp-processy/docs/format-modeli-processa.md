# Формат модели процесса

Файл `modeli/processy/PROC-xxx.json`. Одна модель — один процесс карты. Проверка: `node "<плагин>/scripts/progon.mjs" PROC-xxx` (из рабочей папки).

Модель нужна трём потребителям сразу: **движку** (исполняет события и ловит нарушения), **столу** (очереди, поля шага, решения) и **подключению к Zoho** (где живут записи и какие поля заводить). Поэтому у всего есть ключ, тип и основание.

## Верхний уровень

```json
{
  "format": 1,
  "process": {},
  "desks": [],
  "records": [],
  "fields": [],
  "numbers": {},
  "steps": [],
  "rules": [],
  "paths": [],
  "questions": [],
  "assumptions": [],
  "sources": []
}
```

## process

| Ключ | Что |
|---|---|
| `id` | `PROC-012` |
| `ref` | код в карте: `RLF-2` |
| `title` | название как в карте |
| `start` | с чего начинается (событие-вход) |
| `fact` | точка факта процесса — что доказывает, что процесс закончен |
| `owner_desk` | стол владельца процесса, ему уходят сигналы просрочки |
| `map_edition` | редакция карты, по которой собрано: `4.181` |

## desks — столы

`{ "code": "DESK-012", "title": "Стол кассира", "role": "исполнитель", "source": "..." }`. Роль — одна из: `владелец`, `исполнитель`, `получатель сигнала`, `участник`. Роль «любой стол с оператором» — `code: "ИНИЦИАТОР"`.

## records — записи

Что за объект данных ведёт процесс и где он живёт.

`{ "key": "cash_day", "object": "OBJ-022", "title": "Кассовый день", "home": "Creator", "module": null, "source": "карта objs OBJ-022 dom" }`

`home` — система по карте (`objs[].dom`): `CRM`, `Creator`, `Books`, `Practice`, `Projects`, `Конвейер`, `внешняя`, `вне платформы`. `module` — техническое имя модуля, если оно известно (листы карты «Языком платформы», `zoho.listy` → «1 · Модули»), иначе `null`.

## fields — поля

`{ "key": "cash_day.status", "record": "cash_day", "id": "FLD-0183", "label": "Статус кассового дня", "type": "enum", "values": ["открыт", "приём закрыт", "сдан в сейф", "закрыт", "закрыт с расхождением"], "source": "G302" }`

`type`: `text`, `number`, `money`, `date`, `datetime`, `bool`, `enum`, `multienum`, `ref`, `file`, `user`. У `enum` и `multienum` значения обязательны — без них стол не покажет выбор, а Zoho откажет на чужом значении. `id` — ключ поля в карте, если он есть (`flds`, связи `step_flds`).

## numbers — числа

```json
"cutoff": { "kind": "time", "value": 1050, "inclusive": false, "unit": "минуты от полуночи", "source": "O1 · стр. 7" }
```

`kind`: `time` (минуты от полуночи), `minutes`, `days`, `money`, `count`, `percent`. `inclusive`: `true` — граница входит, `false` — не входит, `null` — источник не сказал (движок на границе ответит «не определено», и это вопрос). Не указан — обычное сравнение.

## steps — шаги

```json
{
  "key": "STEP-0082", "no": 4, "action": "выдача в окна выдачи",
  "desk": "DESK-012", "desks": [],
  "record": "cash_operation",
  "deadline_min": 360, "deadline_source": "стр. 7",
  "fields": [
    { "field": "cash_operation.receipt", "role": "пишет", "required": true },
    { "field": "cash_operation.hold_reason", "role": "пишет", "required": { "when_decision": "удержать" } },
    { "field": "cash_operation.amount", "role": "читает" }
  ],
  "decision": { "title": "Итог выдачи", "options": ["выдано", "отказ"] },
  "next": [ { "when": "выдано", "step": "STEP-0083" }, { "when": "отказ", "step": "END" } ],
  "fact": "закрытый ваучер CV-01 с номером, подписанный получателем",
  "entry": "распоряжение кассе выдано",
  "source": "карта STEP-0082 · презентация стр. 6"
}
```

- `next` не указан — следующим считается шаг с номером на единицу больше (как в маршруте платформы). `when: "*"` — при любом решении. `step: "END"` — процесс на этом заканчивается.
- Шаг открывается, когда сделан предшественник, который к нему ведёт, и не осталось открытых предшественников.
- `fields[].required`: `true`, `false` или `{ "when_decision": "…" }`.

## rules — правила

Каждое правило проверяется, когда стол делает шаг `step`. Не прошло — исход `on_fail`.

```json
{
  "id": "R-limit", "step": "STEP-0081", "kind": "сравнение",
  "when": null,
  "test": { "op": "<=", "a": { "field": "order.amount" }, "b": { "number": "day_limit" } },
  "on_fail": { "outcome": "отказ", "text": "заказ выше дневного лимита", "to": null },
  "source": "стр. 8 · O5"
}
```

`kind` — для отчёта: `обязательно`, `сравнение`, `время`, `порядок`, `разделение`, `гейт`, `значение`, `текст`. Правило, которое не удаётся выразить выражением, пишется с `kind: "текст"` и без `test` — движок его не проверяет, прогон показывает его как проблему.

`on_fail.outcome`: `отказ` (шаг не сдаётся), `сигнал` (шаг сдаётся, адресат узнаёт), `эскалация` (как сигнал, но вверх по лестнице). `to` — код стола.

### Выражения

Значения:

| Запись | Что даёт |
|---|---|
| `{ "field": "order.amount" }` | значение поля: уже записанное или вводимое на этом шаге |
| `{ "number": "day_limit" }` | значение числа |
| `{ "now": "time" }` | время события — минуты от полуночи |
| `{ "decision": "STEP-0098" }` | решение, принятое на шаге (на текущем — вводимое) |
| `"строка"`, `12`, `true` | как есть |

Операции:

| `op` | Аргументы | Истина, когда |
|---|---|---|
| `filled`, `empty` | `a` | поле заполнено / пусто |
| `==`, `!=` | `a`, `b` | равно / не равно |
| `in` | `a`, `b` — массив | значение в списке |
| `<`, `<=`, `>`, `>=` | `a`, `b` | сравнение; если одна сторона — число с `inclusive`, равенство решает `inclusive` (для `<=` и `>=`) |
| `done` | `step` | шаг уже сделан |
| `not_same_actor` | `step` | этот шаг делает не тот человек, что сделал `step` |
| `and`, `or` | `args` — массив | логика; неизвестное даёт «не определено» |
| `not` | `a` | отрицание |

## paths — пути

Правильные ходы процесса, из которых генератор выводит сценарии. Нужен хотя бы один путь от старта до конца; для каждого варианта каждого решения — путь, который через него проходит.

```json
{ "name": "касса: обычный день", "expect": "чисто", "events": [
  { "step": "STEP-0079", "desk": "ИНИЦИАТОР", "actor": "Инициатор", "at": "D+0 09:30", "values": { "deal.amount": 800 }, "decision": null }
] }
```

`at` — `D+день ЧЧ:ММ`. `actor` — имя человека, нужно для разделения обязанностей. `expect` — `чисто` или `сигнал`, если путь законно даёт сигнал.

## questions — вопросы

Только то, что не нашлось ни в карте, ни в решениях, ни в презентации, ни в практике.

```json
{
  "id": "Q-hold-days", "address": { "kind": "rule", "id": "R-hold" },
  "question": "Сколько рабочих дней платёж может стоять удержанным до эскалации?",
  "options": [ { "text": "2 рабочих дня, как у удержания ЭБ", "why": "решение по контролю закупок: удержание не дольше 2 рабочих дней", "recommended": true }, { "text": "1 рабочий день", "why": "" } ],
  "ask": "владелец", "blocks": true,
  "searched": "карта G… · презентация RLF стр. … · ИДЕИ.md раздел 1 — срока нет"
}
```

`ask`: `владелец`, `аналитик`, `стол`, `настройка`. `blocks`: без ответа модель неисполнима. `searched`: где искали — чтобы не спрашивать второй раз.

## Формат 2: время, циклы, таймеры, визы

Всё ниже необязательно: модель формата 1 исполняется так же. Добавлено по итогам первой волны — то, что агенты не смогли выразить и записали текстом.

### calendar — рабочий календарь

```json
"calendar": { "tz": "Asia/Dubai", "start": "2026-09-14", "workdays": [1,2,3,4,5], "hours": ["09:00","18:00"], "holidays": [] }
```

Не указан — берётся этот. Основание: A32, календарь по Дубаю для всех контуров. Рабочая неделя и часы взяты из практики ОАЭ, это допущение до слова владельца. День `D+0` — это `start`. Даты в полях и путях («2026-09-20», «2026-09-20T10:00») считаются от него.

### Сдвиг времени

`{ "minutes": n }`, `{ "hours": n }`, `{ "days": n }`, `{ "workdays": n }`, `{ "workhours": n }`.

- `workdays: n` — до конца рабочего времени n-го рабочего дня после дня события. `workdays: 0` — до конца текущего рабочего дня. Событие в нерабочее время считается с ближайшего рабочего дня.
- `workhours: n` — n часов только рабочего времени.

### Новые значения в выражениях

| Запись | Что даёт |
|---|---|
| `{ "now": "abs" }` | момент события — минуты от D+0 |
| `{ "now": "date" }` | начало дня события |
| `{ "date": "2026-10-01" }` | дата как момент |
| `{ "field": "trip.return_date", "plus": { "workdays": 5 } }` | любое значение со сдвигом (`plus` работает у всех значений-моментов) |
| `{ "step_time": "STEP-0081" }` | когда шаг сделан (последний проход) |
| `{ "step_desk": "…" }`, `{ "step_actor": "…" }` | кто сделал шаг |
| `{ "desk": "current" }`, `{ "actor": "current" }` | стол и человек этого события |
| `{ "passes": "STEP-0081" }` | сколько раз шаг пройден |
| `{ "external": "PAY-EXECUTED" }` | когда пришло внешнее событие |
| `{ "signoff_desk": "поле" }`, `{ "signoff_actor": "поле" }` | кто завизировал поле |
| `{ "count": "поле" }` | сколько значений в поле |
| `{ "calc": "-", "args": [a, b] }` | `+ - * / min max floor` над числами и моментами |

Строки-даты в сравнениях `< <= > >=` сравниваются как моменты.

### Новые операции

| `op` | Истина, когда |
|---|---|
| `same_day` (`a`, `b`) | оба момента в одном календарном дне |
| `workday` (`a`) | момент в рабочее время рабочего дня |
| `contains_all` (`a`, `b`) | в наборе `a` есть все значения `b` |
| `subset` (`a`, `b`) | все значения `a` есть в `b` |

### Шаги

| Ключ | Что |
|---|---|
| `deadline` | срок шага: сдвиг плюс необязательные `from` (значение-момент; по умолчанию — открытие шага), `to` (стол, список столов или `{ "field": … }`) и `when` (выражение). Можно дать список: работает первый, у которого `when` истинно. Так задаются сроки, зависящие от ветки. `deadline_min` из формата 1 работает как раньше |
| `next` на шаг с меньшим номером | **возврат на доработку**: шаг снова открыт, всё, что за ним, снова ждёт |
| `max_passes` | сколько раз шаг можно пройти (с возвратами) |
| `optional: true` | шаг может остаться несделанным к концу, например второй независимый вход |
| `notify` | `[{ "to": …, "text": …, "when_decision"?: …, "when"?: … }]` — уведомление при сдаче шага; это не нарушение, путь остаётся чистым |
| `requires_external` | id внешних событий, без которых шаг не сдать |

### Поля шага

- `required: { "when": выражение }` — обязательно по значению другого поля или по факту шага. Можно вместе с `when_decision`.
- `by_desk: "DESK-050"` или список — поле вносит другой стол внутри шага: виза. В событии пути виза записывается так: `"signoffs": { "поле": { "desk": "DESK-050", "actor": "Имя" } }`. Если визы нет или визирует не тот стол, это отказ.

### Адресаты

`on_fail.to`, `deadline.to`, `timers[].to`, `notify[].to` — код стола, список кодов или `{ "field": "deal.from_desk" }`.

### timers — таймеры без действия стола

```json
{ "id": "T-reminder", "from": { "step": "STEP-0335" }, "after": { "workdays": 10 },
  "until": { "step": "STEP-0336" }, "pause_while": { "op": "==", "a": { "field": "act.on_hold" }, "b": true },
  "to": ["DESK-004"], "text": "10 рабочих дней без ответа контрагента", "source": "G249" }
```

- `from` — от чего отсчитывать: `{ "step" }` (сделан), `{ "opened" }` (открыт), `{ "start": true }` или любое значение-момент (`{ "field": … }`).
- `until` — шаг или выражение, которые снимают таймер.
- `pause_while` — пока выражение истинно, таймер не срабатывает.
- После возврата на доработку таймер от шага взводится заново.

Таймер проверяется на каждом событии и на проверке часов — событии пути `{ "tick": true, "at": "D+12 09:00" }`.

### externals — внешние события

`"externals": [{ "id": "PAY-EXECUTED", "title": "Платёж исполнен в PROC-011", "process": "PROC-011" }]`. Событие пути: `{ "external": "PAY-EXECUTED", "at": "…" }`. Так выражаются межпроцессные гейты: шаг ждёт факт из другого процесса.

### Новые типы полей

`percent` и `table` — табличная часть. Выражения над строками таблицы пока не поддерживаются: такие правила остаются текстом.

### Что по-прежнему текстом

Порядок между записями очереди, проверки по другим экземплярам и записям, поиск по справочнику, пересчёт валют по курсу, запрет действия над записью вне шага. Это уровень платформы (очереди, справочники, права), а не одного процесса. Такие правила записываются `kind: "текст"` с пометкой в `source`: «уровень платформы».

## assumptions и sources

- `assumptions`: `{ "address": {...}, "taken": "что взято", "by_analogy_with": "откуда", "why": "..." }` — всё, что взято не из источника.
- `sources`: `{ "ref": "карта 4.181 STEP-0079…0087", "where": "dannye/megamozg.json" }` — чем пользовались.
