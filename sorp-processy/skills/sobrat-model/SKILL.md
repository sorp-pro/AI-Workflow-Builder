Довести модель процесса от карты до «логика готова» и выложить её вопросы людям.

Плагин — только код. Карта, презентации и модели — данные команды: они лежат в
**рабочей папке** (там, где открыт Claude) и в репозиторий плагина не попадают.

## 1. Проверь рабочую папку

```bash
node -e "const fs=require('fs');for(const p of ['dannye/megamozg.json','dannye/istochniki','modeli/processy'])console.log(fs.existsSync(p)?'есть  ':'нет   ',p)"
```

- **Нет `dannye/megamozg.json`** — остановись и скажи человеку одной строкой:
  нужна выгрузка карты «Мегамозг» (JSON) в `dannye/megamozg.json`; её даёт тот,
  кто ведёт карту. Без карты модель не из чего собирать — не собирай по памяти.
- **Нет `dannye/istochniki/<дата>/Презентации`** — можно работать, но скажи, что
  модели выйдут беднее: презентации — второй источник после карты. Их выгружают с
  общего диска коннектором Google Drive.
- `modeli/processy` нет — создастся сам.

## 2. Пакет процесса

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/paket.mjs" PROC-xxx
```

Без кода — пакеты по всем процессам карты. Пакет — всё из карты про один процесс:
шаги, поля, объекты и их системы, столы, решения владельца, требования, страницы
презентаций. Агент читает пакет, а не всю карту.

## 3. Модель — агентом

Запусти агента `model-processa` (из этого плагина) на каждый процесс. В задании
передай **код процесса** и **путь плагина** — агент читает инструкцию из плагина,
а переменной `CLAUDE_PLUGIN_ROOT` у него нет:

> Процесс PROC-xxx «название». Плагин: `${CLAUDE_PLUGIN_ROOT}`. Рабочая папка: <текущая>.

Несколько процессов — несколько агентов параллельно, но не больше десяти за раз:
каждый агент читает пакет в сотни килобайт.

Агент вернёт итог: строку прогона, число вопросов, дыры, расхождения источников и
«чего не хватает формата». Не пересказывай всё — дай человеку сводку по процессам и
отдельно то, что требует его решения.

## 4. Прогон

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/progon.mjs"
```

Одна строка на модель. Готова, когда: ошибок 0, дыр 0, сбоев 0, неопределённостей 0,
у каждого решения есть путь. Не готова — верни агенту с выводом прогона, не правь
модель молча сам.

## 5. Вопросы — на общую страницу

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/voprosy.mjs" PROC-xxx PROC-yyy
```

Скрипт пишет документы вопросов и перечень `vyhod/processy/voprosy/batch.json`.
Выложи их на страницу вопросов инструментом Artifact:
`action: "write_db"`, `db_op: "batch"`, записи — из `batch.json`
(`collection: "processy"`, `doc_id`, `file_path`).

Адрес страницы — в `SORP_VOPROSY_URL`. Нет адреса — спроси человека ссылку на
страницу вопросов команды. Её нет вовсе — опубликуй свою из шаблона
`${CLAUDE_PLUGIN_ROOT}/shablony/voprosy.html` с `capabilities: {"db": {"rules": [{"path": "processy", "read": "view", "write": "admin"}, {"path": "otvety", "read": "view", "write": "interact"}]}}`
и дай человеку ссылку.

Документ, который уже есть на странице, пиши с `if_version`: прочитай его
`read_db` перед записью, если версия неизвестна.

Скажи человеку одной строкой: сколько вопросов выложено, по каким процессам, и что
новые на странице появляются сами — обновлять её не нужно.

### Пока агенты работают

Чтобы вопросы уходили на страницу, не дожидаясь конца волны, запусти слежение
(Monitor, `persistent: true`):

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/sledit.mjs"
```

На каждую строку «модели: …» — шаг 5 для названных процессов.

## Нельзя

- Писать в Zoho, CRM и Catalyst. Логика сначала сходится на модели.
- Класть карту, презентации и модели в репозиторий плагина — он публичный.
- Выдумывать ответ вместо вопроса. У каждого шага, поля, числа и правила — основание.
