Проверить, что процесс проходится руками через экран так же, как в прогоне.

## Что нужно

- Локальный репозиторий **SORP Platform** — путь в `SORP_PLATFORMA` или спроси у
  человека. Страница стенда (`web/procsim.html`, `web/src/pages/ProcSim.tsx`) и
  набор `web/tests/процессы-имитация.spec.ts` живут в платформе. Их нет в ветке
  человека — скажи об этом, не пиши их заново.
- Установленные зависимости платформы (`web/node_modules`) и браузеры Playwright.

## 1. Выпуск

Из рабочей папки с моделями:

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/v-platformu.mjs" "<путь к SORP Platform>"
```

Пересобирает `web/src/lib/proc-sim/dvizhok.ts` и `modeli.ts`. Модели с ошибками
проверки не выпускаются — скажи какие.

## 2. Проверка типов

```bash
cd "<путь к SORP Platform>/web" && npx tsc --noEmit -p tsconfig.json
```

## 3. Тесты

Подними стенд (Browser pane / preview, не Bash) и прогони набор против него.

**Полный набор гоняй с собранного клиента, а не с dev-сервера.** Vite под часовым
прогоном падает (на Windows — код 3221226505), и тогда всё, что шло после падения,
краснеет «сервер не отвечает»: сотни падений, к моделям отношения не имеющих.
Собери один раз (`npx vite build` в `web`) и отдавай статику
(`npx vite preview --outDir ../client/dist --port <порт> --strictPort`). Dev-сервер
годится для точечного повтора по одному процессу, пока правишь страницу.

```bash
cd "<путь к SORP Platform>/web" && SORP_BASE=http://localhost:<порт> npx playwright test "tests/процессы-имитация.spec.ts" --project=desktop --workers=4
```

На каждый путь модели — тест кликами; на процесс — ещё три нарушения: «шаг раньше
очереди», «шаг чужим столом» и «два шага с разделением делает один человек» (эта
берёт правила `not_same_actor` и ждёт исход, записанный в самом правиле, — обычно
отказ, но бывает и сигнал). Упало — прочитай `test-results/<тест>/error-context.md`.

Прежде чем разбирать падения, **посмотри, жив ли сервер**: если в журнале есть
`ERR_CONNECTION_REFUSED` или `Could not connect`, эти падения ничего не значат —
подними стенд и повтори только упавшие процессы (`-g "PROC-(023|045|048) "`).

Причины падений бывают трёх видов, различай их:

- **модель** — путь вносит поле, которое пишет другой шаг; значение не из списка;
  стол шага не тот. Верни процесс в модель (навык `sobrat-model`).
- **страница** — элемента нет, два одинаковых элемента. Это правка платформы;
  опиши её человеку, в модель не лезь.
- **сам тест** — ждали отказ там, где правило по решению даёт сигнал; длинному пути
  не хватило времени (`test.slow()`). Правь тест, но сначала убедись, что правило
  действительно такое: подгонка ожидания под поведение прячет настоящую ошибку.

Покажи человеку снимок страницы стенда с пройденным путём.

## Нельзя

- Коммитить, пушить и открывать PR в платформе без просьбы человека.
- Гонять набор против боевого адреса: только локальный сервер или dev.

## Роли: кто делает шаг, а не только что делает

Карточки ролей и сценарии по ним собираются отдельно и до стенда:

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/roli.mjs"            # карточки столов из карты и моделей
node "${CLAUDE_PLUGIN_ROOT}/scripts/roli-scenarii.mjs"   # смежный стол · замещение · совмещение · день роли
```

Находка сценария по ролям — не всегда ошибка модели. «Замещение не описано» значит,
что молчит источник: это вопрос людям, а не правка модели. Что нашлось про
совмещение столов — заводи вопросом в модели и выкладывай на стенд.
