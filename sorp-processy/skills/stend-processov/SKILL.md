Проверить, что процесс проходится руками через экран так же, как в прогоне.

## Что нужно

- Локальный репозиторий **SORP Platform** — путь в `SORP_PLATFORMA` или спроси у
  человека. Страница стенда (`web/procsim.html`, `web/src/pages/ProcSim.tsx`) и
  набор `web/tests/процессы-имитация.spec.ts` живут в платформе. Их нет в ветке
  человека — скажи об этом, не пиши их заново.
- Установленные зависимости платформы (`web/node_modules`) и браузеры Playwright.

## 1. Выпуск

Из рабочей папки с моделями:

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/v-platformu.mjs" "<путь к SORP Platform>"
```

Пересобирает `web/src/lib/proc-sim/dvizhok.ts` и `modeli.ts`. Модели с ошибками
проверки не выпускаются — скажи какие.

## 2. Проверка типов

```bash
cd "<путь к SORP Platform>/web" && npx tsc --noEmit -p tsconfig.json
```

## 3. Тесты

Подними dev-сервер платформы (Browser pane / preview, не Bash) и прогони набор
против него:

```bash
cd "<путь к SORP Platform>/web" && SORP_BASE=http://localhost:<порт> npx playwright test "tests/процессы-имитация.spec.ts" --project=desktop --workers=4
```

На каждый путь модели — тест кликами; на процесс — ещё «шаг раньше очереди» и
«шаг чужим столом». Упало — прочитай `test-results/<тест>/error-context.md`.

Причины падений бывают двух видов, различай их:

- **модель** — путь вносит поле, которое пишет другой шаг; значение не из списка;
  стол шага не тот. Верни процесс в модель (навык `sobrat-model`).
- **страница** — элемента нет, два одинаковых элемента. Это правка платформы;
  опиши её человеку, в модель не лезь.

Покажи человеку снимок страницы стенда с пройденным путём.

## Нельзя

- Коммитить, пушить и открывать PR в платформе без просьбы человека.
- Гонять набор против боевого адреса: только локальный сервер или dev.
