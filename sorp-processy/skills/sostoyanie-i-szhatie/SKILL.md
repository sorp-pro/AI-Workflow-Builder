Разговор сжимается — сам, когда заполнится, или по команде. После сжатия остаётся краткое
изложение, а подробности пропадают. Качество не теряется, только если всё, что нужно для
продолжения, лежит **в файлах**, а не в памяти разговора.

## Два файла

- `vyhod/processy/sostoyanie-ruchnoe.md` — **ведёшь ты**. Только то, что нельзя восстановить из
  файлов и стенда.
- `vyhod/processy/sostoyanie.md` — **собирается скриптом**: ведомая часть плюс факты с диска и стенда
  (модели, итог прогона, отметки «занято», выкладки вопросов, вопросы и ответы).

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/sostoyanie.mjs" zapisat --prichina "что произошло"
```

Хуки плагина делают это сами: перед сжатием разговора файл записывается, а после сжатия его
содержимое возвращается в разговор. Твоя часть работы — держать ведомую часть актуальной.

## Что писать в ведомую часть

Коротко, фактами, без пересказа разговора:

1. **Что запущено сейчас.** Номер запуска агентов, фоновые задачи (что делают, как перезапустить),
   расписание. Команда продолжения, если оборвётся.
2. **Решения человека**, которые меняют работу: модель агентов, порядок, что выкладывать, что
   не трогать. С датой.
3. **Что ждёт человека**: вопросы, споры, отклонённые ответы, выбор — с кодами процессов.
4. **Следующие шаги** по порядку, с командами.
5. **Грабли**, на которые уже наступили, — чтобы не наступить после сжатия (например: агенты
   работали не из той папки; отчётам агентов не верить без своего прогона).

Не пиши туда то, что уже лежит в файлах: содержимое моделей, итоги прогона, списки вопросов.

## Когда обновлять

- запустил фоновую работу или остановил её;
- человек принял решение;
- закончился этап (волна, обход, внесение ответов);
- перед тем как надолго ждать.

Обновил ведомую часть — сразу `zapisat`.

## Когда сжимать

Сжимать разговор стоит **на границе этапа**: этап закрыт итогом, ведомая часть обновлена,
`zapisat` выполнен. Не сжимай посреди разбора, когда в разговоре есть выводы, ещё не записанные
в файлы. Предложи человеку: «этап закрыт, состояние записано — можно сжать разговор (/compact)».

## Экономия контекста без потери качества

- **Большой вывод — в файл, в разговор — хвост.** `… > vyhod/processy/<что>.txt` и `tail`/`grep`
  нужного, а не весь вывод. Прогон всех моделей — одна строка на модель, не подробности.
- **JSON — выборкой.** `node -e` с нужными полями, а не весь документ.
- **Читай файлы кусками**: offset/limit, grep по ключу. Не перечитывай файл, который только что правил.
- **Тяжёлое чтение — агенту.** Пакеты процессов, транскрипты, большие модели читает агент и
  возвращает вывод; в основной разговор — только вывод.
- **Итог агентов не пересказывай целиком.** Таблица по процессам и отдельно — то, что требует
  решения человека.
- **Регулярные сообщения фоновых задач** — одной строкой и только при изменении.
- **Не повторяй проверенное.** Проверенный факт записан в файл — ссылайся на файл.

Экономия не должна вырезать проверку: свой прогон после агентов, чтение нужного места модели
перед правкой и сверка со стендом остаются обязательными.
